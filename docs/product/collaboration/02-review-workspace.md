# PicBind 实时协作（二期）

> Version: v1.0
> Status: Planning
> Priority: P0

---

# 一、项目背景

PicBind 已具备以下能力：

- 图片上传
- 图片压缩
- 用户间图片共享
- WebRTC P2P 数据通信
- TURN 中继
- Cloudflare R2 临时文件存储
- Emoji、文本实时同步

目前用户已经可以进入同一个房间查看同一张图片。

下一阶段目标：

> 将"图片分享"升级为"图片协作"。

---

# 二、目标

让多个用户可以像坐在同一台电脑前一样，共同查看和讨论图片。

一期实现三个核心能力：

- 实时图片批注（Annotation）
- 实时鼠标 / 激光笔（Live Pointer）
- 同步视角（Viewport Sync）

---

# 三、功能一：实时图片批注（Annotation）

## 功能介绍

允许房间成员在图片上进行实时标记。

所有操作立即同步给所有在线用户。

图片本身不会修改。

所有批注均为 Overlay。

# 发送前图片压缩优化

## 需求描述

在图片分享流程中，结合 PicBind 核心图片压缩能力，对待发送图片进行智能检测。

当用户准备发送图片时，如果图片较大或存在明显压缩空间，提示用户进行压缩优化。

---

## 功能流程

用户选择图片

↓

点击发送

↓

检测图片大小、尺寸、压缩收益

↓

如果需要优化：

提示用户压缩

↓

用户选择：

- 压缩后发送
- 发送原图

↓

压缩完成后生成优化版本

↓

用户选择发送压缩后的图片

---

## 房间内图片管理

压缩完成后的图片保留在当前 Room 中。

用户可以查看最近处理过的图片：

- 原图
- 压缩版本
- 压缩效果

并选择发送。

---

## 目标

- 降低图片传输大小
- 提升分享速度
- 减少存储和网络成本
- 强化 PicBind 图片压缩核心能力

## 数据同步

所有绘制均同步对象，而不是同步画布。

例如：

```json
{
  "type":"annotation.create",
  "tool":"arrow",
  "id":"uuid",
  "userId":"userA",
  "data":{
      "x1":100,
      "y1":120,
      "x2":400,
      "y2":300,
      "color":"#ff0000",
      "width":4
  }
}
```

其他客户端收到后直接创建对象。

---

- PC

# 六、整体通信协议

DataChannel 消息建议统一格式：

```json
{
    "type":"annotation.create",
    "roomId":"xxx",
    "userId":"xxx",
    "timestamp":123456789,
    "payload":{}
}
```

事件建议统一命名：

```
annotation.create

annotation.update

annotation.delete

pointer.move

pointer.leave

viewport.sync

viewport.follow

room.state

image.change
```

# 十、技术原则

- 所有实时消息优先走 WebRTC DataChannel。
- 图片文件通过 Cloudflare R2 分发，仅传输文件 URL 或对象标识，不通过 DataChannel 发送图片内容。
- 所有批注均采用图片坐标系（Image Coordinate），确保跨设备显示一致。
- 批注对象采用增量同步，仅同步对象变更，不同步整张画布。
- 新成员加入时，由房主同步当前房间状态（图片、批注、视角），无需依赖服务端持久化。
- 服务端仅负责房间管理、信令与 TURN，不参与实时批注数据转发（P2P 可用时）。
