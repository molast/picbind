# PicBind Workspace 3.0 协作图片系统设计文档（V1）

## 文档目标

本次优化重点不是普通图片编辑，而是建立一套：

- 工作区（Workspace）图片协作机制
- 图片协作状态管理
- 参数化图片处理系统
- 图片修改提议（Proposal）机制
- Activity 操作历史系统
- 图片回溯机制
- 协作者 / Owner 协同审批机制

核心原则：

> 普通图片 = 生成新图片
>
> 协作图片 = 参数叠加，不立即生成图片

---

# 一、图片状态定义

Working 区域中的图片分为两种状态：

## 1. 普通图片（Normal）

特点：

- 不参与协作
- 拥有自己的图片处理按钮
- 操作后生成新图片
- 保存后进入 Working 列表
- 右侧仅显示图片信息

---

## 2. 协作图片（Collaborative）

特点：

- 同一时间只能有一张图片处于协作状态
- 图片卡片显示：

```text
[协作中]
```

状态标识。

协作图片：

- 所有处理操作统一放到右侧面板
- 图片卡片不显示更多按钮
- 图片不能删除
- 图片操作不立即生成图片
- 所有修改均记录为参数
- 所有参数形成可回溯历史

---

# 二、图片删除规则

## 普通图片

点击删除：

弹出确认框：

```text
删除图片

图片删除后：

○ 返回 Library 仓库
○ 直接删除

[取消] [确认]
```

---

## 协作图片

删除按钮不可用。

点击提示：

```text
当前图片正处于协作中，不可删除。

请先停止协作。
```

# 六、普通图片与协作图片处理机制

---

## 普通图片

任何操作：

```text
处理
↓

生成新图片

↓

保存

↓

加入 Working
```

原图不变。

---

## 协作图片

任何操作：

```text
修改参数

↓

参数叠加

↓

实时预览

↓

不生成图片
```

例如：

```json
{
  "crop": {},
  "color": {},
  "rotate": {},
  "draw": {}
}
```

---

最终保存时：

弹窗：

```text
保存图片

○ 替换原图
○ 保存为新图片

[取消] [保存]
```

---

# 七、协作修改提议系统（Proposal）

---

流程：

协作者：

```text
点击裁剪
```

↓

打开裁剪弹窗

↓

预览效果

↓

确认

↓

弹出：

```text
等待 Owner 确认
```

---

注意：

此时：

- 不生成图片
- 不传输图片
- 不上传 Blob

仅发送：

```json
{
  "type": "crop",
  "params": {
    "x": 100,
    "y": 50,
    "w": 800,
    "h": 600
  }
}
```

---

# 八、Proposal 数据结构

```json
{
  "proposal_id": "",
  "image_id": "",
  "user_id": "",
  "base_commit_id": "",
  "operations": [
    {
      "type": "crop",
      "params": {}
    }
  ],
  "message": "",
  "status": "pending",
  "created_at": ""
}
```

状态：

```text
pending
approved
rejected
later
```


展示：

- 原图
- 参数预览图
- 放大
- 缩放

---

```text
同意
拒绝
稍后
```

---

## 同意

立即：

```text
参数合并
```

Activity：

```text
已通过
```

---

## 拒绝

输入：

```text
拒绝原因（可选）
```

协作者收到：

```text
修改被拒绝
原因：
xxx
```

Activity：

```text
已拒绝
原因：xxx
```

---

## 稍后

关闭弹窗。

Activity：

```text
待处理
```

Owner 可重新打开。

# 十、图片参数协议

由于协作图片完全由参数控制，因此需要独立协议。

建议模块：

```text
picbind-image-protocol
```

---

协议格式：

```json
{
  "version": 1,
  "operations": []
}
```

---

Operation：

```json
{
  "id": "",
  "user_id": "",
  "time": "",
  "type": "",
  "params": {}
}
```

---

支持：

```text
crop
color
draw
rotate
resize
filter
annotation
ai
```

---

# 十二、回退机制

Owner：

点击：

```text
回退到此版本
```

弹窗：

```text
确认回退？

回退后：

后续历史将被删除。
```

---

确认：

```text
commit4

↓

commit2
```

删除：

```text
commit3
commit4
```

---

协作者收到通知：

```text
Owner 已回退图片版本
请同步最新版本
```

---

# 十三、Commit 检测

协作者提交时：

检查：

```text
base_commit_id
```

---

如果不是最新：

提示：

```text
当前图片已更新。

请先同步最新版本后再提交。
```

---

流程：

```text
协作者
↓

获取最新 Commit

↓

重新编辑

↓

重新提交
```

---

# 十五、核心设计原则

## 普通图片

```text
操作 = 新图片
```

---

## 协作图片

```text
操作 = 参数
参数 = Commit
Commit = Activity
Activity = 历史
历史 = 可回退
```

---

## 协作本质

不是：

```text
多人同时修改图片
```

而是：

```text
多人共同维护一条图片参数历史链
```

这将使 Workspace 3.0 从：

```text
图片仓库
```

升级为：

```text
可协作、可审批、可回溯的图片工作流系统。
```
